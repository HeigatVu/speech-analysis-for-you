# Repository Analysis: Speech Analysis for You (SAY)

**Analyzed:** 2026-09-02 · **Version:** 0.2.0 · **License:** MIT · **Package:** `speech-analysis-for-you` (imports as `speech_features`)

---

## 1. What this project is

SAY is a **research/descriptive, Python-first library** for speech and sound analysis of
**reviewed Vietnamese speech data**, aimed at cohort characterisation and hypothesis
exploration in neurodegenerative and clinical-linguistics research. It is explicitly
positioned as **not a diagnostic or screening tool**: no normative ranges, no cutoffs,
no trained models embedded, no ASR/diarization/forced alignment. A core design
invariant is that transcripts must be **human-reviewed** before the library consumes
them — automated tools may prepare annotations externally, but SAY treats them as
reviewed input only.

The library is **label-free**: extraction consumes PCM WAV audio plus a reviewed
transcript document, and produces features without requiring diagnostic labels.

## 3. Architecture

### 3.1 Data flow

```
PCM WAV ──┐
          ├─► extract/extract_batch ──► FeatureBundle
SpeechDocument ─┘                        ├─ recordings  (pandas, per-recording features)
   (JSON v2 / CHAT / JSON v1)            ├─ utterances  (pandas, + utterance_id/start_s/end_s)
                                         ├─ issues      (structured codes, never silent zeros)
                                         └─ provenance  (SHA-256 of inputs, config, versions)
```

### 3.2 Module map

| Module | Role |
|---|---|
| `document.py` (30 sym.) | `SpeechDocument` versioned model; `load_document`/`save_document`; JSON v2 native, JSON v1 deterministically migrated, CHAT subset read/write via a `FORMATS` dispatch registry |
| `formats/json.py`, `formats/chat.py` | Decode/encode pairs; CHAT is a CLAN-**compatible subset**, not a CLAN clone |
| `schema.py` (47 sym.) | Manifest v2, task-spec validation, stable error/issue codes (`STABLE_ERROR_CODES`, `STABLE_ISSUE_CODES`) |
| `extraction.py` (39 sym.) | `extract` / `extract_batch` / `extract_recording` / `extract_manifest`; row/target isolation |
| `audio.py` | PCM WAV reading (`read_wav`), width/format validation |
| `result.py` | `FeatureBundle` + `FeatureIssue` + provenance contract |
| `catalog.py` (23 sym.) | **Static** `PACKS` registry (`MappingProxyType`), `list_features` queries, 485-feature catalog v1 |
| `features/acoustic/` | phonation, quality, resonance, rhythm, spectrum, timing, advanced submodules |
| `features/linguistic/` | clinical, diversity, morphosyntax, task_scores |
| `features/motor/` | annotation-driven motor speech (DDK) intervals |
| `features/standardized/` | lazy openSMILE eGeMAPS adapter (returns NaN + `MISSING_OPTIONAL_DEPENDENCY` if extra not installed) |
| `legacy/ad/` | 0.1-era AD evaluation/pipeline/tasks, exposed with `DeprecationWarning`, removal scheduled 0.3.0 |
| `cli.py` | `say-features` entry point: `validate` / `convert` / `extract` / `list-features`; exit codes 0 (ok/warn), 1 (partial failures), 2 (invalid input/config) |

### 3.3 Design decisions worth noting

- **Static pack registry.** `PACKS` is a deliberately immutable mapping — adding a pack
  (e.g., a future child pack) requires an intentional source change and validation.
  No entry-point discovery, no dynamic plugins. This trades extensibility for
  reproducibility of the catalog.
- **NaN + issue, never a fabricated zero.** Unavailable features emit a structured
  issue row with a stable code instead of silently filling values.
- **Provenance everywhere.** Every bundle records input SHA-256 hashes, configuration,
  package/catalog versions, target speakers, and annotation sources.
- **Evidence-tiered catalog.** Every feature carries an evidence level
  (`systematic_review` → `derived_companion`), a domain (15 domains), task scope
  (8 task IDs), disorder scope (15 disorders incl. AD, MCI, PPA, PD, ALS, HD, ataxia…),
  and language scope (independent → specific) — an unusually rigorous metadata schema
  for a research feature library.

## 5. Project history and direction

Git history shows a clear **pivot and consolidation**: the project began as an
Alzheimer's-disease speech pipeline (now `speech_features.legacy.ad`, deprecated with a
0.3.0 removal window) and was re-architected into the multi-pack v0.2 library through a
steady sequence of feature commits (neurodegenerative feature library, eGeMAPS pack,
motor speech pack, nonlinear voice measures, neuro-linguistic task measures) interleaved
with hardening fixes (annotation validation, placeholder rejection, timing-span
semantics). The most recent commit is housekeeping only (index/session files).

Documentation is extensive — five core guides (feature extraction, transcript formats,
feature catalog, neurodegenerative guide, 0.1→0.2 migration) plus `docs/research/`,
`docs/implementation/`, and a Vietnamese Alzheimer's feature library plan — but see
observation O1 below.

## 6. Observations and risks

- **O1 — Docs are untracked.** `docs/` was deliberately removed from git
  ("chore: stop tracking local docs"), so README links (`docs/feature-extraction.md`
  etc.) are broken on a fresh clone, and the rendered catalog docs are not reproducible
  from the repo. Consider tracking the generated docs or noting their generation step
  (`tools/render_neuro_feature_inventory.py`).
- **O2 — Legacy shims on a clock.** `speech_features.pipeline`, `.evaluation`, and
  `.tasks` emit DeprecationWarnings and are slated for removal in 0.3.0; the test suite
  still imports them (3 warnings), so removal will require test migration first.
- **O3 — No CI config in repo.** Quality gates (pytest, ruff) exist and pass but are
  documented as local commands; a CI workflow would make the current green state durable.
- **O4 — Single-language focus.** Vietnamese token/word grouping is baked into the
  document model and several features; this is a feature, not a bug, but contributors
  should know the catalog's `language_scope` metadata is the only portability lever.
- **O5 — Complexity concentration.** Total cyclomatic complexity ≈2,025 across 26.7k
  LOC; the largest modules (`schema.py`, `extraction.py`) carry the most surface and
  are the most blast-radius-sensitive per codegraph (e.g., `load_document` has 64 callers,
  `list_features` 33).

## 7. Summary

SAY is a mature, well-tested (754 passing tests), cleanly linted, narrowly depended
research library with an unusually disciplined contract layer: versioned documents,
stable issue/error codes, provenance capture, evidence-tiered feature metadata, and an
immutable pack registry. The main open items are housekeeping — putting docs back under
version control (or generating them in CI), migrating legacy-shim tests ahead of the
0.3.0 removal, and adding a CI workflow to protect the currently green state.

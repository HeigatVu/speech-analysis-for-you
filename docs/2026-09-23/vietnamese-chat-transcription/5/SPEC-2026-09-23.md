# Specification: `say_transcribe` v5 — automatic transcription + `%mor`/`%gra`

**Status:** draft, pending human approval
**Research:** [RESEARCH-2026-09-23.md](./RESEARCH-2026-09-23.md)
**Plan:** [PLAN-2026-09-23.md](./PLAN-2026-09-23.md)

## 1. Scope and non-goals

Produce one Chatter-valid `.cha` file per session: main tier (`*PAR`/`*INV`, `•start_ms_end_ms•`
bullets) plus `%wor`, `%mor` and `%gra` dependent tiers, generated automatically the way DementiaBank
Delaware's transcripts are shaped (main tier + `%wor` + `%mor` + `%gra`; 460 of 462 Delaware files
carry `%wor`) and the way `batchalign`/`talkbank-tools` produce them (transcribe → utterance segment
→ align → morphotag), adapted to Vietnamese.

**Out of scope**, dropped from v4:

- `session-annotations.v1` JSON, approved/draft annotation review, task spans, turn roles.
- Clapperboard task-boundary detection.
- `tell-inspired-v1` preprocessing (SoX/GSM, loudness normalization, DeepFilterNet3 denoising,
  Silero VAD/timing features) for the main v5 pipeline. The §8 pilot-comparison amendment
  reintroduces Silero VAD as a scoped research spike (ASR windowing aid, not a CHAT boundary
  source), not a reversal of this line.
- SAY JSON v2 manifest and label-free `speech_features` output.

No task-clip cropping, no per-task acoustic features, no human-in-the-loop annotation contract.
Speaker labels are auto-diarized and human-relabeled directly in the `.cha` file (§4); there is no
separate approval artifact.

## 2. Pipeline

1. Load the master WAV. Verify SHA-256 (recorded in the `.cha` `@Comment` provenance line, §3; no
   separate annotation file to compare against, so there is no `SOURCE_HASH_MISMATCH` code in v5 —
   see D7 in PLAN).
2. Select the declared channel explicitly (`--channel N`). Never mean-downmix; a quiet/silent
   channel would attenuate the speech signal (`AGENTS.md` §2, carried from v4).
3. Expose an in-memory 16 kHz mono `float32` view for ASR without writing resampled audio to disk.
4. PhoWhisper-medium ASR produces timed segments and word-level `start_end` timestamps (for `%wor`,
   §3). These segments stand as CHAT utterance boundaries directly (no separate
   utterance-segmentation model) — batchalign itself falls back to
   ASR boundaries for every language it has no utseg model for, Vietnamese included (RESEARCH §2,
   §4 row 1). §8 amends this step for the five pilot sessions only: VAD-guided windowing plus
   Vietnamese CTC alignment produce an alternate segmentation, compared against this baseline.
5. pyannote diarization produces a per-utterance speaker draft (§4).
6. Underthesea 9.5.0 groups ASR tokens into `_`-joined Vietnamese words per utterance (NFC, tones,
   `d`/`đ` preserved; never groups across an utterance boundary).
7. Stanza `vi` (UD-VTB), run pretokenized on the `_`-joined words with MWT explicitly disabled,
   produces UD-style POS/lemma/dependency output per utterance.
8. Render `%wor` from the ASR word timestamps, `%mor`/`%gra` from the Stanza output per the
   render.py rules (§3), and write one `.cha` file for the session.

## 3. CHAT contract

### Headers

```
@UTF8
@Begin
@Languages: vie
@Participants: PAR Participant, INV Investigator
@ID: vie|corpus|PAR|||||Participant|||
@ID: vie|corpus|INV|||||Investigator|||
@Media: <session-id>, audio
@Comment: source_sha256 <hash>
@Comment: speaker labels draft, auto-diarized; review before use
@End
```

`@Languages` is `vie` (ISO 639-3), matching batchalign's own `to_stanza()` conversion path
(RESEARCH §5). No `@PID` — v5 has no annotation-file provenance chain to carry it from.

### Main tier and bullets

`*PAR:` / `*INV:` lines, one per ASR/diarization-derived utterance, terminated with a
`•start_ms_end_ms•` bullet using the ASR segment's own boundaries (§2 step 4).

### `%wor`

One item per word in surface order: `word start_end_ms`, with utterance-final punctuation carrying
no span — the Delaware reference shape. A `_`-joined word's span runs from its first syllable's
start to its last syllable's end. Word spans come from PhoWhisper word-level timestamps (§2 step 4);
if they are unavailable for an utterance, omit `%wor` for that utterance only (main tier line and
bullet are kept) and record one session-level warning `CHAT_WORD_TIMING_UNAVAILABLE` with the
utterance's ordinal position (no utterance text in the warning).

### `%mor`

One item per `_`-joined word, in surface order: `pos|lemma[-Feat]`, where `pos` is the UD UPOS tag
lowercased and `lemma` keeps the `_` joiner (do not run through batchalign's `render.py:921`
`target.replace("_", "")`, which assumes `_` is CHAT clitic notation, not a Vietnamese word-joiner —
RESEARCH §3, §4 row 3). `-Feat` is appended only when Stanza's `feats` string is non-empty; UD-VTB
publishes very few morphological features for Vietnamese, so most items are expected to be
`pos|lemma` with no suffix (RESEARCH §4 row 7). A literal `,` renders as `cm|cm` (RESEARCH §3, three
citations).

### `%gra`

One item per word: `i|head|REL`, 1-based index, uppercase UD relation label, `:` replaced with `-`.
The sentence root has `head == 0` and `REL == ROOT`; this pairing is a joint invariant, never one
without the other (RESEARCH §3). The terminator token (utterance-final punctuation) gets
`(n+1)|root|PUNCT` where `n` is the last word index.

### Failure path

If Stanza fails to produce a parse for an utterance (empty/malformed ASR text, model error), omit
both `%mor` and `%gra` for that utterance only — the main tier line and bullet are kept — and record
one session-level warning `CHAT_MORPHOSYNTAX_UNAVAILABLE` with the utterance's ordinal position (no
utterance text in the warning).

## 4. Speakers

pyannote diarization runs on the full channel-selected audio and assigns each ASR utterance to a
diarized speaker cluster. The cluster with the greater total talk time becomes `*PAR`; the other
becomes `*INV`. This is a draft: the `@Comment: speaker labels draft, auto-diarized; review before
use` line marks it as such, and a human corrects `*PAR`/`*INV` labels directly in the `.cha` text —
there is no separate relabeling file or re-import step (D5 in PLAN).

## 5. CLI

```text
say-transcribe diagnose
say-transcribe run MASTER.wav --channel N --out DIR [--device cuda|cpu]
say-transcribe evaluate GOLD_DIR PREDICTIONS_DIR --out REPORT.json
say-transcribe compare MASTER.wav --channel N --out DIR --expected-sha256 HASH
    [--vad-threshold 0.0-1.0] [--device cuda|cpu]
```

`compare` is the §8 pilot-comparison entry point: it writes the baseline, VAD-guided, and
VAD-guided-aligned variants into `DIR` and never overwrites an existing file there.

Exit codes: `0` success, `2` validation/configuration, `3` unavailable dependency/model, `4`
pipeline failure.

Stable error codes (v4 core, minus the annotation-only codes that have nothing left to validate
against): `INVALID_AUDIO_CHANNEL`, `GPU_UNAVAILABLE`, `MODEL_UNAVAILABLE`, `WORD_GROUPING_UNALIGNED`,
`CHAT_VALIDATION_FAILED`, plus the new `CHAT_MORPHOSYNTAX_UNAVAILABLE` and
`CHAT_WORD_TIMING_UNAVAILABLE` (§3). The §8 `compare` subcommand adds: `VAD_UNAVAILABLE` (Silero
VAD or its ONNX runtime failed), `INVALID_VAD_WINDOWS` (VAD windows out of order or out of range),
`ALIGNMENT_UNAVAILABLE` (the Vietnamese CTC model or forced-align call failed), `SOURCE_HASH_MISMATCH`
(reintroduced: the master WAV no longer matches the pilot's `--expected-sha256`, not an annotation
file as in v4), `INVALID_ARGUMENT` (bad CLI input, checked before any I/O), and
`CHAT_UTTERANCE_TIMING_UNAVAILABLE` (a segment produced no in-range timed span at all — distinct
from `CHAT_WORD_TIMING_UNAVAILABLE`, which is about individual word spans within an otherwise timed
utterance). `ASR_REPETITION_SUSPECTED` is a warning, not an exit code: the segment looked like a
Whisper repetition loop or an unrecognized `<unk>` token and was replaced with the CHAT `xxx`
marker. `OUTPUT_EXISTS` applies to both `run` and `compare`: never overwrite a manual transcript or
an earlier automatic version. `EVALUATION_FAILED` applies to `evaluate`.

Dropped from v4: `INVALID_ANNOTATIONS`, `UNAPPROVED_ANNOTATIONS`, `CLAP_NOT_FOUND`,
`CLAP_COUNT_MISMATCH`, `SOX_UNAVAILABLE`, `SOX_GSM_UNAVAILABLE`, `FFMPEG_UNAVAILABLE`,
`LOUDNESS_UNMEASURABLE`, `DENOISER_UNAVAILABLE`, `MODEL_INTEGRITY_ERROR`,
`PREPROCESS_ALIGNMENT_ERROR`, `INVALID_PREPROCESS_ARTIFACT` — all belonged to annotation review or
`tell-inspired-v1` preprocessing, both out of scope (§1). `VAD_UNAVAILABLE` and
`SOURCE_HASH_MISMATCH` are reinstated by §8 for the `compare` path only; they do not appear on
`run`.

Logs and errors expose only stable codes, positions, pseudonymous IDs, public versions, and hashes.
Never emit transcript text, tokens, waveform data, absolute paths, credentials, or raw exceptions
(carried from `AGENTS.md` §2, unchanged).

## 6. Evaluation

Development uses the most complete curated session; held-out uses non-overlapping participant
windows from other sessions. Report syllable error rate (primary), CER, frozen-Underthesea WER
(diagnostic), 250 ms-collar DER (diagnostic against the diarization draft), `%mor`/`%gra` tier
agreement (POS accuracy, UAS/LAS against a small hand-checked set), format/Chatter-validation pass
rate, counts, and seeded 2,000-resample clip-bootstrap intervals (carried from v4 §8). No clinical
threshold is invented before measurement — UD-VTB's published UPOS 81.48/UAS 58.82/LAS 51.49 are
news-domain numbers, not a promise for conversational speech (RESEARCH §6).

## 7. Data classification

| Class | Allowed | Never |
|---|---|---|
| Master audio (participant speech; health-research context) | Read locally under `/shared-data/...` | Git, logs, error messages, tracked docs |
| ASR/diarization intermediate output (segments, speaker clusters) | Process memory / private output dir outside git | Git, tracked docs |
| `.cha` output (transcript + `%mor` + `%gra`) | Private output dir | Git (private corpus output is never tracked) |
| Absolute filesystem paths | Process memory only | Logs, errors, `.cha` `@Comment` lines |
| Aggregate evaluation metrics (§6) | Tracked docs | Per-utterance text, per-speaker timestamps in tracked docs |

## 8. Pilot comparison amendment (2026-09-24)

The original v5 path remains the baseline. The timing review found that its
20-second ASR windows are not reliable CHAT utterance boundaries. For the five
pilot sessions, produce three separate automatic outputs: baseline, VAD-guided
PhoWhisper, and VAD-guided PhoWhisper with Vietnamese CTC word alignment. Never
overwrite a manual `.cha` or an earlier automatic version.

On the two VAD-guided paths, run Silero VAD 6.2.3 ONNX on the selected
channel's in-memory 16 kHz view. VAD selects speech to transcribe; it does not
declare CHAT utterance boundaries. Restore absolute sample offsets after ASR.
Use a pilot default threshold of 0.2, exposed as `--vad-threshold` for
microphone calibration; the 0.5 default missed more p001 reference intervals.
The aligned path splits only after alignment, at sentence-final punctuation or
an interword pause over 700 ms. Keep original Vietnamese text and mark words or
utterances untimed when alignment cannot support a positive, in-range span.
Use the noncommercial Vietnamese CTC model only for this approved research
comparison. Model access and heavy imports remain lazy.

Before decoding, compare the master WAV SHA-256 with the expected pilot source
hash. Keep native PCM unchanged and select channel 0 explicitly for these pilot
masters; never average stereo channels. Store outputs under an ignored private
directory. Reports contain aggregate counts only. Current single-microphone
speaker labels remain drafts; future PAR/INV microphones require a separate
per-channel design.

Acceptance is a three-version comparison for p001–p005, zero fabricated or
nonpositive spans, and a p001 aligned candidate with at least 90% timed
utterances. Text-quality gates alongside timing: no repetition loop or `<unk>`
reaches the main tier untagged (every such segment carries
`ASR_REPETITION_SUSPECTED` and renders as `xxx`, never as the raw hallucinated
or `unk` text); p001 bag-of-syllable recall against the human transcript is at
least the plain-baseline path's own recall (0.88 in the pilot measurement);
and VAD windows touch at least 95% of human-timed p001 utterances. If any
candidate misses a target or drops audible speech, keep all versions labelled
draft and report the failure. Manual p001 timing is a review aid, not exact
gold.

## 9. Open questions

1. Does Chatter accept `_`-joined Vietnamese words in `%mor`/`%gra` items? Gated by a fixture test
   before the renderer is trusted (T8 in PLAN).
2. Are PhoWhisper segment boundaries good enough to stand in as CHAT utterance boundaries, given
   Vietnamese has no dedicated utseg model to compare against (RESEARCH §2, §8)?
3. Does pyannote give a usable two-speaker `*PAR`/`*INV` draft on the pilot audio?
4. How accurate is UD-VTB on conversational/clinical Vietnamese speech, versus its published
   news-domain scores (RESEARCH §6)?

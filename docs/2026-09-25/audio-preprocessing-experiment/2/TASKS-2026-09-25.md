## T2: P0 profile — bandpass, GSM round trip, loudnorm [done]

**Goal:** the common preprocessing stage shared by P0, PF, and PD: channel-selected mono → 200 Hz–
3.4 kHz band-pass → 8 kHz → FFmpeg `libgsm` round trip (padding trimmed to input length) → 16 kHz →
FFmpeg two-pass `loudnorm` (`I=-23:TP=-1:LRA=50:linear=true`).

**Acceptance:**
- Output is mono 16-bit-equivalent PCM at 16 kHz with the same sample count as the input (padding
  trimmed).
- A synthetic tone above 3.4 kHz is attenuated relative to one inside the passband (band-pass check).
- `normalization_type` (`linear`/`dynamic`) and measured I/TP/LRA are recorded per call; a synthetic
  input with source LRA above 50 is asserted to report `dynamic` (fallback detected, not hidden).
  **Deviation (2026-09-25, verified):** measured LRA above 50 is unconstructible — EBU R128's
  relative gate (I − 20 LU) bounds reachable LRA around 33 (ffmpeg 6.x max observed: 14.3), so the
  literal trigger can never fire. The test pins the reachable fallback trigger instead (true-peak
  overflow forcing `dynamic` despite `linear=true`); the observable contract — fallback flagged, not
  hidden — is identical.
- Missing `ffmpeg`/`libgsm` raises `CODEC_UNAVAILABLE`; a `loudnorm` pass-2 that can't parse stats
  raises `LOUDNORM_FAILED`. Both messages contain no absolute paths.
- Tests skip (not fail) when `shutil.which("ffmpeg")` is None, so CI without ffmpeg still passes.

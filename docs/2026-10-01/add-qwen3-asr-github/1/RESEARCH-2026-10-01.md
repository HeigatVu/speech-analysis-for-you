# Research: Qwen3-ASR integration and pyannote reactivation

## Sources

1. [QwenLM/Qwen3-ASR (GitHub)](https://github.com/QwenLM/Qwen3-ASR) — official model family repository: "open-source series of ASR models developed by the Qwen team at Alibaba Cloud, supporting stable multilingual speech/music/song recognition, language detection and timestamp prediction".
2. [transformers model doc: Qwen3 ASR](https://github.com/huggingface/transformers/blob/main/docs/source/en/model_doc/qwen3_asr.md) — native transformers integration (contributed 2026-06-26), API usage, language list.
3. [Qwen/Qwen3-ASR-1.7B (Hugging Face)](https://huggingface.co/Qwen/Qwen3-ASR-1.7B) — model card, Apache-2.0, arxiv 2601.21337, `qwen3_asr` architecture tag.
4. [Qwen/Qwen3-ASR-1.7B-hf (Hugging Face)](https://huggingface.co/Qwen/Qwen3-ASR-1.7B-hf) — transformers-native checkpoint used by the model doc examples.
5. [pyannote/speaker-diarization-3.1 (Hugging Face)](https://huggingface.co/pyannote/speaker-diarization-3.1) — model card with access conditions, requirements, benchmark.
6. [vinai/PhoWhisper-large (Hugging Face)](https://huggingface.co/vinai/PhoWhisper-large) — comparison baseline checkpoint.

## Facts

- **Qwen3-ASR checkpoints.** Two sizes: `Qwen/Qwen3-ASR-1.7B-hf` (~1.7B, the model the user asked for) and `Qwen/Qwen3-ASR-0.6B-hf`. The `-hf` checkpoints are the transformers-native ports; the bare `Qwen/Qwen3-ASR-1.7B` repo is the original release. Pin the `-hf` variants: they load through `AutoProcessor` / `Qwen3ASRForConditionalGeneration` with no custom code.
- **Inference API (transformers >= the 2026-06-26 integration).** `processor.apply_transcription_request(audio=...)` builds the chat template; `model.generate(**inputs)` then `processor.decode(ids, return_format="transcription_only"|"parsed"|"raw")` yields text and a `{"language", "transcription"}` dict. Language can be forced (`language="Vietnamese"` or `"vi"`), and free-form context/hotwords bias decoding via `prompt=`. Batch inference accepts lists of audios/languages/prompts.
- **Vietnamese support.** Qwen3-ASR-1.7B officially lists Vietnamese (`vi`) among its 31 languages — it is in scope for this corpus.
- **Word timestamps.** The companion `Qwen/Qwen3-ForcedAligner-0.6B-hf` supports only zh, en, yue, fr, de, it, ja, ko, pt, ru, es — **not Vietnamese**. So Qwen3-ASR cannot supply word-level timings for Vietnamese audio through the official aligner; its `AsrSegment`/`WordTiming` fields stay null and WER/CER are computed from segment text only. PhoWhisper (Whisper-family) keeps its segment timestamps. Timestamps are not part of the comparison anyway — the spec scores text error and speaker attribution.
- **Baseline.** `vinai/PhoWhisper-large` exists and is the PhoWhisper family "large" checkpoint the user named; the repo's `PhoWhisperBackend` already drives PhoWhisper checkpoints via `transformers` ASR pipeline and can take the large model id unchanged.
- **pyannote gating (the consent the user granted).** `pyannote/speaker-diarization-3.1` is MIT-licensed but gated: user conditions must be accepted on **two** repos (`pyannote/segmentation-3.0` and `pyannote/speaker-diarization-3.1`) and an access token from `hf.co/settings/tokens` must be provided (env `HF_TOKEN`/`HUGGING_FACE_HUB_TOKEN` or `huggingface-cli login`). Conditions text: "agree to share your contact information to access this model" (collected to know the pyannote.audio userbase; occasional product emails).
- **pyannote runtime.** Requires `pyannote.audio >= 3.1`; ingests mono 16 kHz; the pipeline itself averages multichannel input to mono — our repo never feeds it raw multichannel: it receives the explicitly selected channel's in-memory 16 kHz mono view, so the AGENTS.md no-downmix rule is preserved at the pipeline boundary.
- **Local environment (verified).** `.venv` already has `transformers 5.17.0` (with `Qwen3ASRForConditionalGeneration` importable — verified), `torch 2.14.0`, `huggingface-hub 1.32.0`, `pyannote.audio 4.0.7`. No new package installs are required for either model; only HF access (token + accepted conditions) gates pyannote weights.

## Applicability

- Everything needed for the SPEC's two comparisons is available: Qwen3-ASR runs through transformers-native classes on the existing lazy-load backend pattern; pyannote is already integrated as `PyannoteBackend` and only the gating/token path plus the silent-fallback policy stand between the code and a live run.
- The models measure what the spec asks: Qwen3-ASR vs PhoWhisper-large transcription error (WER/CER on verified `.cha` references), and pyannote vs WavLM speaker attribution (PAR/INV agreement) on the same sessions.
- Qwen3-ASR's lack of Vietnamese word timing is a recording caveat, not a blocker: the spec's ASR metrics are text-based.

## Refinements

- Pin `Qwen/Qwen3-ASR-1.7B-hf` (not the bare repo) as `Qwen3AsrBackend`'s default `model_id`; force `language="Vietnamese"` at inference for deterministic, fair comparison (PhoWhisper is Vietnamese-tuned and has no language-detect step).
- Use `return_format="transcription_only"` output and map each generated transcript into one `AsrSegment` with null timings; keep `AsrResult`/normalization identical to the PhoWhisper path so both models score through `evaluate.py` unchanged.
- pyannote reactivation is a policy change in `cli.py` plus token plumbing, not new research: default `pyannote`, explicit `--diarizer wavlm|pyannote`, stable error code `MODEL_UNAVAILABLE`/`PYANNOTE_TOKEN_MISSING` when gating blocks loading. The human's consent covers the two repos' conditions on their HF account; nothing in code clicks accept.
- PhoWhisper-large comparison pins `vinai/PhoWhisper-large` in the benchmark while the pipeline default stays `vinai/phowhisper-medium`.

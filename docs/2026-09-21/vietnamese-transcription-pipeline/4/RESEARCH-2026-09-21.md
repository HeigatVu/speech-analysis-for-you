# Research digest: Vietnamese pilot and TELL-inspired audio branch

**Specification:** [SPEC-2026-09-21.md](./SPEC-2026-09-21.md)  
**Plan:** [PLAN-2026-09-21.md](./PLAN-2026-09-21.md)

## Applicability to the pilot

The pilot contains five continuous stereo WAV masters (~92.3 minutes): one 44.1 kHz and four 48 kHz, all signed 32-bit containers. Three sessions have an active left channel and nearly silent right channel, so a mean stereo downmix would attenuate useful speech. Eleven task labels are present in protocol material but not all boundaries are curated. Only one CHAT file is near-complete; other files are partial or malformed. Hardware is visible but `nvidia-smi` cannot communicate with the NVIDIA driver.

Therefore the reliable baseline is: human-approved span annotations, explicit channel selection, native-rate feature audio, a fake ASR backend for tests, and a blocked real PhoWhisper-medium pilot. The processed branch must be opt-in and evaluated beside—not substituted for—the native branch.

## What the TELL paper supports

The TELL paper describes four stages: SoX common-channel normalization, FFmpeg EBU R128 loudness normalization, FullSubNet denoising, and Silero VAD ([paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC11200269/)). It does not publish enough parameters to reproduce its exact pipeline: the SoX effect graph, loudness target, denoiser checkpoint/configuration, and Silero thresholds are unspecified. Its public companion repository ([TELL source](https://github.com/telltoolkit/TELL_source_code)) uses a pyannote SAD path in `talking_intervals.py` and does not contain the complete four-stage implementation.

The actionable interpretation is a clearly labeled **TELL-inspired** profile with pinned, inspectable parameters—not a claim of exact TELL reproduction. The paper’s “compression factor of 8” refers to the GSM Full Rate codec ratio; it is not a request for an additional SoX `compand` effect.

## Selected implementation decisions

| Decision | Choice | Reason |
|---|---|---|
| Audio route | Parallel opt-in profile | Protects native Vietnamese tone/fricative measurements and enables A/B evidence. |
| Common-channel stage | SoX GSM Full Rate round-trip, decode PCM16, high-quality 16 kHz resample, 200 Hz high-pass + 3.4 kHz low-pass | Matches the published description while making the ambiguous filter topology explicit. |
| Loudness | FFmpeg two-pass `loudnorm`, `I=-23`, `LRA=7`, `TP=-2` | EBU R128-compatible and measurable; fail closed when statistics are unavailable. |
| Denoising | DeepFilterNet3 v0.5.6, pinned model hash, optional/lazy | Modern maintained substitute for unavailable FullSubNet integration; no auto-download in tests. |
| VAD | Silero v6.2.2 CPU ONNX, separate feature family | Keeps existing energy VAD stable and makes multilingual timing claims testable. |
| Activation | Opt-in with a gate | Native audio remains the default until ASR, VAD, artifact, and privacy checks pass. |

## Source evidence for the selected tools

- [SoX GSM source](https://github.com/chirlu/sox/blob/master/src/gsm.c) and [SoX manual](https://manpages.debian.org/testing/sox/sox.1.en.html): GSM is an 8 kHz codec; host installation must be checked rather than assumed.
- [FFmpeg `loudnorm` documentation](https://ffmpeg.org/ffmpeg-filters.html#loudnorm) and [EBU R128](https://tech.ebu.ch/docs/r/r128v4_0.pdf): two-pass EBU loudness workflow and target terminology.
- [DeepFilterNet v0.5.6 source](https://github.com/Rikorose/DeepFilterNet/tree/v0.5.6), tag commit `978576aa8400552a4ce9730838c635aa30db5e61`, and model SHA-256 `49c52edc8947ae1f9bf50d81530beaf3a2c3245aeaf34b6f31ff535cd22284d2`.
- [Silero VAD v6.2.2 adapter](https://github.com/snakers4/silero-vad/blob/v6.2.2/src/silero_vad/utils_vad.py), tag commit `60b7ffa243625ebdc1070275a29f18c87843786a`, and ONNX SHA-256 `1a153a22f4509e292a94e67d6f9b85e8deb25b4988682b7e174c65279d8788e3`.

Silero’s defaults (0.5 threshold, 250 ms minimum speech, 100 ms minimum silence, 30 ms padding, 16 kHz support) are implementation starting points, not Vietnamese validation results. T11 must score a manually reviewed private interval sample.

## Refine

1. Keep native and processed profiles separate in both manifests and feature names.
2. Add a sidecar contract before adding any processed feature pack.
3. Use integer-sample intervals and hash checks to detect alignment drift.
4. Keep optional tools out of core imports and fail with stable dependency codes.
5. Evaluate Vietnamese ASR and VAD on private data before any promotion decision.
6. Cite repository source links in the plan/tasks so implementation can be reviewed against concrete code, not vague inspiration.

## Unresolved questions

- Exact PhoWhisper-compatible Torch/Transformers pins, runtime, and peak VRAM remain unverified until CUDA is repaired.
- SoX availability and GSM handler availability differ across developer machines; the runbook must probe both.
- DeepFilterNet3’s effect on Vietnamese tones and fricatives is unknown; processed acoustic packs stay shadow-only.
- A defensible Silero threshold adjustment, if any, requires manual Vietnamese interval scoring.
- No ASR or clinical acceptance threshold is set before the first private baseline.
